## High-Level Findings

- The current paper evidence is now in `benchmarks/paper_results/`, not in legacy result folders or root `*_eval.csv` files.
- The model architecture is reasonable for retrieval-constrained exact matching: residual six-layer GIN, multi-scale pooled readout, normalized graph embeddings, hard negatives, and a multi-positive partition coverage loss.
- The loss is conceptually correct, but the implementation needs tightening before a stronger resubmission: positive subgraph truncation can drop query nodes, K-hop coverage targets are bounded/truncated, and `src/model.py` has drifted from the canonical trainer defaults.
- There is no MCTS/MCST benchmark. The relevant experiment is MC dropout in `scripts/compare_recall.py`; it computes old/new/MC paths partially, but only writes standard new-model R@1/R@5/R@20 into `final_tables.txt`, so it should be treated as exploratory.
- `SubgraphMatching_tmp/` is third-party solver source/build material. It is important for reproducibility but should not live as loose project code. Move to `third_party/SubgraphMatching` or replace with a submodule/build script.

## Model And Loss Assessment

The current model/loss is a solid baseline, but not yet clean enough to claim that coverage is fully validated.

Keep:

- Six-layer residual GIN with LayerNorm and multi-scale mean/max/sum readout.
- Hierarchical contrastive loss over fine and coarse positives.
- Hard negative coarse partitions.
- Multi-positive partition coverage loss for multi-partition queries.
- FAISS top-K retrieval plus exact Glasgow verification.

Fix before resubmission:

- In `scripts/train_jigsaw_model.py`, `_extract_subgraph_from_adj` randomly subsamples large positive regions. For positive contexts, query/global nodes must always be preserved before sampling extra context nodes.
- K-hop training currently bounds/truncates multi-partition targets for memory. Record both the full true partition set and the bounded training target so the paper can report coverage honestly.
- `src/model.py` loss defaults differ from `scripts/train_jigsaw_model.py`: trainer uses `alpha=0.2`, `beta=0.0`, partition temperature `0.05`; `src/model.py` currently defaults to `alpha=0.5`, `beta=0.2`, partition temperature `0.1`.
- `src.evaluate` has a CLI default of `--top_k 5` even though the actual paper/retrieval fallback is K=20.
- Add coverage diagnostics during training and evaluation: target partition count, retrieved target count, coverage recall, skipped empty targets, and query type breakdown.

Required ablations:

- Coverage strength: `gamma=0`, `0.1`, `0.5`, `1.0`.
- Retrieval budget: `K=5`, `10`, `20`, `50`.
- Loss components: fine only, fine+coarse, fine+coarse+hard negatives, full loss with coverage.
- Architecture: residual GIN versus plain GIN, multi-scale readout versus final-layer readout.
- Query family: report single, multi-fine, multi-coarse, and K-hop separately; K-hop should be framed as a bounded retrieval stress test.
